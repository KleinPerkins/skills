# Separate ecosystem discovery from Codex project entry

Owner: KleinPerkins/skills. ADR number, canonical identity and lifecycle are assigned by doc-warden.

## Context and revision relationship

The accepted docs/plans/agent-route-client-parity-primary-routing-v1.md requires three-client exposure, primary-checkout preference, old-index compatibility and the existing scoring contract. This proposal intentionally replaces those requirements for the new release. Preserve the accepted file byte-for-byte; record the successor relationship in the new canonical plan/ADR and mutable index. Its explicit v2 successor procedure must be respected; if v2 canonical artifact placement differs, record an owner-adjudicated cross-reference rather than silently treating the old plan as revoked.

docs/adr/0001-agent-route-feedback-loop.md and its companion plan remain drafts. They are not accepted constraints and do not authorize feedback collection. Their proposed learned multiplier and feedback log will not be implemented. Preserve their bodies and record a superseded/withdrawn draft disposition in the appropriate mutable index only through governed publication.

Skills ADR0002's declared sibling-asset/package ownership and ADR0007's exposure semantics remain in force. Existing doc-warden, ecosystem-orchestrator and dev contracts remain authoritative. This proposal does not amend Codex model routing or AWA.

## Decision

1. Extract the reusable discovery, metadata mining, indexing and deterministic ranking into a single Skills-owned global tool capability, proposed ID ecosystem-index. Keep reusable code generic and machine policy/configuration external. No compatibility wrapper for the old router runtime.
2. Add a thin ecosystem-search skill for capability lookup and task-context preparation. Both it and the narrow agent-route may use the tool; neither owns a second cache or dependency catalog. Installation must use the existing capability/package mechanism. New cross-capability dependency behavior, if required by qualification, is an explicit owner decision rather than an ad hoc installer copy.
3. Replace agent-route with Codex-only entry instructions, metadata, minimal lifecycle installer and focused validation fixtures. No routing CLI, context miner, scorer, private registry or scheduled job remains inside this skill. An explicit repository is verified directly; search is optional when ownership is unknown.
4. Use three distinct identities: logical repository (provider repository ID when supplied by an authorized source, otherwise normalized credential-free remote identity), clone (physical Git common-directory identity) and worktree (per-worktree Git identity plus current root). Preserve every local location independently. Remote-less repositories remain locally identified and cannot be silently merged with a similarly named project.
5. Treat the index as an observation cache. Authoritative enrollment and exposure are read from their existing owner sources. Curated aliases and permitted roots are local inputs, not mutations to those sources. Declared, observed and inferred facts remain distinguishable; contradictory facts coexist with a conflict result rather than being silently overwritten by source priority guesses.
6. Mine only allowlisted, explicitly storage-eligible fields. Retain bounded descriptions from enrolled metadata, normalized identity, source pointers, explicit relationships and freshness bindings. AGENTS, policy and decision documents supply references/status observations only; do not persist their bodies or let their contents execute as instructions. Ambiguous secret-bearing or noneligible fields are omitted with a bounded reason. Redaction/keyword matching alone is not eligibility proof.
7. Discovery begins with an explicit permitted inventory. Supported inputs: selected native project observations, configured roots, explicit workspace-file inputs and Git worktree metadata for already-permitted repositories. No default recursive home traversal or IDE database scraping. Apply lexical exclusions before access and approved identity exclusions before deeper mining; unknown identity/scope remains blocked pending separate resolution. Discovery never inspects a prohibited tree to prove it should be excluded.
8. Reads use a snapshot without writes. Explicit refresh compares input bindings, updates only affected records and atomically publishes a validated snapshot. Failed enumeration cannot imply deletion; retain previous observations as stale/unverified and expose scan incompleteness. No scheduled refresh ships in v1.
9. Agent-route uses native tools under current tool contracts and owner workspace policy. Reuse suitable attachments; branch/writer checks stay with existing guards. A wrong-project chat receives a supported handoff, never a shell-only move. New chats require explicit applicable authorization. A native attachment establishes placement, not permissions, protection or cleanup rights. No disposable permission-test writes.
10. Retire the old CLI and all client compatibility deliberately. New agent-route exposure is codex only. Legacy installed hooks, jobs, links and state require an exact owned-delta operation after source merge. Generated cache may be discarded; curated inputs require explicit selection and sanitization before transfer. Never bulk-import the old registry or feedback data. Downstream disposition uses ecosystem-orchestrator and recipient governance; source changes do not silently enroll or sync the new capabilities.

## Alternatives

Delete all discovery code: rejects useful reuse and duplicates future search/context work. Keep the old router as the shared platform: retains routing-specific defaults and operational machinery in every consumer. Build a new service/vector database: unnecessary for a small, deterministic local metadata corpus. Chosen: extract tested primitives behind one bounded local interface; ship only two substantive read consumers first.

## Consequences and tradeoffs

The narrow route skill becomes substantially smaller; the total ecosystem runtime is not promised to shrink by the same percentage because valuable extraction/mining behavior is retained. No native safety enforcement is claimed from skill prose. Search uses a frozen synthetic relevance corpus and explanation fields; ranking thresholds are retrieval policy, not permission gates. A missing tool/index cannot block known-project entry.

Proposed layout: global/tools/ecosystem-index for code/tests/schema/lifecycle metadata; global/skills/ecosystem-search for usage instructions; global/skills/agent-route for Codex entry. Proposed IDs and paths must be checked for collisions and package/distribution support at owner review. Begin with no live activation and no automatic installation dependency. Source tests use explicitly supplied tool paths; qualified installation must resolve the approved payload without primary-checkout mutation or undeclared sibling assumptions.

No changes to dev-doctor, downstream repositories, source registries or native settings are smuggled into Skills implementation. Their later changes require their own owner branches and checks. No global memory writes, query history, credentials or raw work content. Privacy eligibility and excluded-access tests are release-blocking.

## Validation and rollback

Trace requirements REQ-ECO-001 through REQ-ECO-013 to the technical contract and execution tasks. Validate retrieval, bounded input access, metadata provenance, clone/worktree separation, cache interruption/concurrency, no-write reads, unsupported-host behavior and existing installer invariants. Independent fresh-context review and normal ready PR delivery are mandatory. Native qualification and cleanup outcomes are recorded separately from source tests.

Before source merge, revise/discard the candidate. After merge, revert through the owner PR path; the new cache is versioned and disposable, never translated into old authoritative state. Live rollback restores only operation-bound owned preimages and refuses unrelated drift. Restoring old source does not automatically re-enable old hooks/jobs or restore downstream delivery. Frozen accepted documents use successors, never in-place rollback edits.

## Owner package resolution

Use the existing source-backed capability layout, with no new generic installer behavior or dependency metadata key. `ecosystem-index` is `kind: tool`, `flavor: 1`, `shape: snapshot`, `post_mgmt: none`, `expose: cursor claude codex`; its actual Python source ships in the tool directory. Include `tool.yml` (`schema: kp-tool/v1`, matching ID/scope/shape, `entrypoint: ecosystem_index.py`), `requirements.txt`, README, the existing proposed code/schema/test paths and a minimal lifecycle script. `ecosystem-search` is a flavor-1 skill exposed to cursor/claude/codex. `agent-route` is a flavor-1 skill exposed only to codex. All three have `post_mgmt: none`. Enrollment and downstream disposition remain D1 owner work, not a side effect of these declarations or metadata-lock regeneration.

The generic installer links skill directories; its tool branch validates `tool.yml` but creates no command link, and it does not run a flavor-1/post_mgmt-none installer. Accordingly no PATH command, virtualenv, dependency download or tool-runtime installation is promised. The source CLI remains `python3 <verified-skills-root>/global/tools/ecosystem-index/ecosystem_index.py`. Consumers resolve the physical installed skill directory, verify its declared Skills source root and Git identity, then explicitly resolve `global/tools/ecosystem-index/ecosystem_index.py` within that same source tree. This dependency is documented in both skill READMEs and `tool.yml` and covered by source/symlink-layout fixtures. No hard-coded primary-checkout path, recursive discovery, PATH fallback, copying or automatic bootstrap. A copied/relocated skill without the verified tool reports unavailable; known-repository routing still works directly. Recipient packaging must separately qualify a complete runtime layout before downstream activation.

Use standard-library JSON for configuration, snapshots and results. Declare `PyYAML==6.0.3` in the tool's requirements file for eligible YAML inputs, reusing the parser family already used by agent-route. The version is a reproducible dependency choice, not a host-availability or security certification. Use the upstream SafeLoader path with closed field/type validation, duplicate-key rejection, bounded nesting/node counts, and rejection of unsupported aliases/tags/multiple documents before field extraction. Do not write a replacement YAML parser or import arbitrary repository code. Search/describe/context read JSON without requiring PyYAML; refresh explicitly reports an unavailable parser for YAML sources and retains prior facts as stale. No command, hook, bootstrap or installer automatically installs dependencies. The lifecycle script performs only read-only prerequisite/source checks; actual dependency provisioning, if needed, belongs to the later exact installation operation.

Packaging acceptance: strict meta parser accepts all three manifests; the tool descriptor exists and matches identity; physical skill resolution reaches the declared tool in a source-backed install; copied/missing/mismatched dependencies refuse explicitly; a missing parser cannot trigger network/pip or turn a partial refresh into a complete result; reads remain write-free and process-free inside the runtime. Validate these with synthetic layouts and access probes, not installed clients. No shared `bootstrap.sh` or metadata-schema change is required.
