# Ecosystem index and Codex entry technical contract

Owner: KleinPerkins/skills. This feature specification requires an approved PRD; canonical identity, lifecycle and approval provenance are recorded by doc-warden.

## Requirement and design traceability

REQ-ECO-001/009/010: consumer boundaries and entry state machine. REQ-ECO-002/003/004: inventory, identity and provenance. REQ-ECO-005/006: search/context interfaces. REQ-ECO-007/008: storage, refresh and failure behavior. REQ-ECO-011/012/013: retirement, authority and delivery. No graphical UX surface is included.

## Interfaces and implementation discretion

Proposed source CLI: python3 global/tools/ecosystem-index/ecosystem_index.py with exactly refresh, search, describe and context subcommands. These names are new and deliberately incompatible with agent-route. The library shares the same parsers and records as the CLI. No second subprocess agent, server or scheduler is introduced.

- refresh --config PATH --cache PATH: explicit bounded source reads and publication to the selected private cache. Requires explicit local scan/metadata-storage policy. No default HOME scan or dependency installation. Its result distinguishes complete, partial and refused, with bounded counters/reason codes and snapshot digest.
- search --cache PATH: query on stdin, bounded to 4096 UTF-8 bytes; optional limit 1..20, default 5. Read-only. Return matches/ambiguous/none/unavailable plus candidates, contribution reasons, provenance and freshness. Do not persist or echo the query in logs/errors.
- describe --cache PATH --id ID: exact entity lookup with distinct repository, clone and worktree locations. Unknown/ambiguous ID is explicit; no filesystem search fallback.
- context --cache PATH --id ID: bounded source-owner, instruction, decision and declared-check pointers. Does not fetch or execute those pointers; the caller must perform permitted live verification before execution. Maximum 20 pointers; report truncation/coverage.

Machine JSON uses a versioned closed schema and deterministic UTF-8 serialization. Unknown fields, duplicate keys, invalid types and unsupported versions refuse. Text rendering derives from the same record. Exit 0 means a valid query/refresh result, including none or partial; exit 2 means invalid input; exit 3 means unavailable/refused source/cache. Result status, not exit 0 alone, determines coverage. Parser/backend exception text containing inputs never escapes.

Implementation may split modules inside the tool's directory while preserving the reviewed interfaces. Existing discover.py, context_mine.py, index_build.py and score.py are sources for selective extraction, not files to copy wholesale. Reuse the repository's approved YAML/metadata parser where needed; do not auto-install PyYAML or invent a partial YAML parser. If no distributable parser dependency fits the existing owner package contract, settle that dependency before implementation merge.

## Data and trust contract

The config owns explicit permitted root records, source-adapter selection, storage-eligible field lists, path/identity exclusions and bounds. It is not an enrollment authority. The cache owns schema version, generation, observed_at, scan coverage, input bindings and entity records. Keep source configuration separate from generated output so refresh cannot overwrite curated choices.

An entity has a typed ID (repository/capability/clone/worktree), parent relationship where applicable, bounded identity/title/description fields, observations and explicit relationship edges. Each observation includes classification (declared/observed/inferred), source kind, source relative pointer, revision nullable, content digest where applicable and observation time. Each edge includes predicate, source/target IDs, classification and supporting pointer; inferred relevance is never emitted as a declared dependency.

Use stable provider identity when already available through an authorized source. Otherwise normalize remote identity without retaining URL userinfo, tokens or query strings. Never follow remote URLs. Distinct local clones share a logical repository but keep their own common-directory identity; worktrees keep separate per-worktree identities. Missing remote/permissions create local/unknown identities, not guessed ownership. No index field named writable, contributable or approved may be derived from location or ranking.

Initial adapters consume opted-in capability metadata, normalized Git metadata and explicit instruction/decision/index pointers. Arbitrary README or policy excerpts are not persistable. Optional description extraction requires an eligible declared field, length bound and secret/ineligible-value refusal. Source files and tool results are data; do not execute repository commands, hooks, credential helpers or embedded instructions. Use read-only local Git commands with bounded time/output and no network; reject remote-helper/path forms requiring execution beyond the approved probe.

Bounds proposed for v1: at most 500 configured root records, 5000 entities, 256 KiB per metadata input, 512 characters per stored description, 32 aliases per entity, 20 MiB snapshot and 60 seconds per refresh. Exceeding a bound yields partial/refused coverage without truncating into a false complete result. Do not increase bounds silently to make a fixture pass.

## Refresh, consistency and storage

Default state location is under XDG_CACHE_HOME/ecosystem-index and config under XDG_CONFIG_HOME/ecosystem-index; resolve HOME fallbacks through standard XDG conventions. Direct CLI paths remain explicit. Private directories/files use 0700/0600. Refuse symlinked writable components, nonregular files and unsupported ownership. No files are written into indexed repositories.

Use one cooperative refresh lock and atomic same-directory publication with validation, fsync and readback. Readers see a complete old or new generation, never partial JSON. Lock contention returns busy without stealing. This is local operational consistency, not exclusion against arbitrary same-user writers. Interrupted refresh preserves the last verified snapshot and removes only its own proven temporary file. Corruption returns unavailable, never silently repairs during a query.

Use input digests/revisions for changed records; cache parser results for unchanged inputs. Scan scope and input eligibility are rechecked each refresh. A failed/missing source preserves prior facts only as stale/unverified. A successful complete enumeration can mark observed locations missing; curated inputs remain in config. Default cache freshness advisory is 24 hours, with exact age always shown. Freshness is an observation, not approval validity. Live authority-sensitive decisions always re-read their governing sources regardless of cache age.

## Codex entry procedure

Agent-route's callable surface is skill prose plus existing native tools. It is invoked for explicit routing, uncertain ownership or detected placement mismatch, not every turn. Proposed dispositions: already-correct, needs-workspace, needs-access, ambiguous and unsupported. They are narration categories, not an authorization token.

Identify owner -> inspect native attachments/current root -> verify Git remote/common/per-worktree directory -> inspect permission information -> defer to owner branch/cleanliness/writer policy. The index is optional. For supported native attach/create, use returned path explicitly in the current turn and verify actual resulting context. A correct root with unknown access is reported as such; first necessary mutation uses normal runtime permission handling. Wrong-project cases use a supported project handoff or ask for explicit new-chat authority. Do not use cd, changed env, filesystem links or a printed path to claim a native move. Never steal another chat's worktree or writer lease.

## Failure handling and rollback

No index -> direct known-project verification; no known owner -> bounded clarification. Stale/partial index -> display limitations, offer explicit scoped refresh. Denied source -> bounded reason without probing alternatives outside scope. Permission denied -> supported runtime access route, no privilege-bypassing relocation. Conflicting metadata -> retain provenance and conflict; no silent resolution. Unavailable native transition -> describe exact operator action; no claimed success.

Version changes rebuild disposable cache from eligible sources, never import old private registry wholesale. Source rollback uses governed revert. Installation and legacy cleanup use separately reviewed target/preimage/owned-delta/rollback manifests and preserve unrelated state. Re-enabling a removed job is a distinct consequence, never an automatic source-revert side effect.

## Verification

Freeze a synthetic query corpus before tuning. Include duplicate capability names, aliases, ambiguous descriptions, remote-less roots, renamed paths, multiple clones, linked worktrees and deliberately misleading metadata. Require all exact-ID cases, all ambiguity/no-result labels and every answerable top-three case to match the frozen rubric. Record baseline and candidate results without claiming real-world performance from fixture ranking.

Instrument filesystem/process access in tests: excluded/unknown roots and outside-scope symlinks remain unopened; search/context perform zero writes and no process execution. Test malicious descriptions, credential-shaped remote URLs, oversized fields, duplicate JSON keys, interrupted publication, reader/refresh overlap, lock contention, partial enumeration and source digest changes. Native entry scenarios cover already-correct, incorrect project, denied/unknown permission, partial attachment and foreign writer. Actual native canary is a later bounded operation, not inferred from these fixtures.

Owner gate includes existing metadata/description/lock/zero-link/install invariants and independent review. Exact commands for new focused tests are established in the implementation task file map; existing owner verifier remains authoritative. No temporary executable directory or HOME override alone is treated as isolation for native app settings.
