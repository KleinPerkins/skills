# Ecosystem discovery and narrow Codex project entry

Canonical product/implementation owner: KleinPerkins/skills. Dev owns local integration; ecosystem-orchestrator owns downstream distribution. Stable requirement identifiers below define this PRD; artifact identity and lifecycle are assigned by doc-warden.

## Problem and affected users

Operators and coding agents need to find existing capabilities, identify a task's owning repository and load the right instructions before editing. The current agent-route bundles discovery, context mining, scoring, indexing, maintenance and workspace movement into one skill. Its useful ecosystem knowledge is coupled to a routing-specific CLI, multi-client movement instructions, primary-checkout preference and a background maintenance installer. Root/cwd checks do not establish Codex write permissions.

The operator requested a substantial reduction of agent-route without backward compatibility, while retaining and repurposing the valuable discovery infrastructure. This is a feature and architecture revision, not a defect exemption. Preserve the accepted client-parity plan as history and supersede its conflicting requirements explicitly through the owner process.

## User value and why now

Before building a new capability, answer whether one already exists. Before implementing a task, identify its source owner, relevant policy/decision pointers and validation entrypoints. Before writing, establish the chat's actual project/workspace and available permission information. One derived index should support the first two needs; a thin agent-route should handle the third and work even when the index is unavailable.

## Current and target behavior

Current: agent-route's private registry/index drives ranked workspace suggestions; installer establishes Cursor session hooks and daily maintenance. Metadata exposes the skill to Cursor, Claude and Codex. Target: Skills owns a reusable ecosystem-index tool, a thin ecosystem-search skill and a Codex-only agent-route skill. The index is a disposable, provenance-bearing local projection. It cannot enroll capabilities, grant permissions, authorize work, register AWA associations or choose a model.

## Journeys and recovery

1. Find a capability: search declared titles/descriptions/aliases; show ranked candidates, reasons, source pointers and freshness. No queries or interaction feedback are retained. An ambiguous result remains ambiguous.
2. Prepare work: inspect an identified repository/capability; return a bounded context packet with source-owner identity and pointers to current instructions, decision records and declared checks. Read those sources live before relying on them.
3. Correct project entry: an explicitly named repository bypasses search. Inspect native attachments, actual execution context and Git identity. Reuse a suitable worktree under existing owner policy. Wrong-project cases produce a precise supported handoff; creating a new chat requires applicable explicit user authority.
4. Recover unavailable index: known-repository work proceeds through direct verification. Unknown ownership requests one focused clarification. Corrupt or stale data is reported rather than treated as authority; refresh is explicit and bounded.

## Non-goals, constraints and guardrails

No backward compatibility for the old agent-route CLI, state schema or Cursor/Claude movement behavior. This does not authorize editing frozen records, silently removing installed artifacts or bypassing downstream ownership. No automatic learned feedback, query history, new daemon/MCP server, embeddings service, model routing, permission manager, workspace lock implementation or AWA replacement. No automatic cloning, cleanup, repository creation, installation, synchronization or execution of indexed commands.

Initial consumers are search and task context, plus optional lookup from agent-route. Dev-doctor adapters, ecosystem-wide impact reports, IDE-private-storage scraping and scheduled refresh are deferred, not hidden completion requirements. Explicit declared relationships may be represented in v1; completeness of a global dependency graph is not claimed.

No reads or writes inside hard-excluded repositories/runtimes, including renamed excluded checkouts; no mcp-builder work. Runtime policy must supply exclusions before discovery. Unknown provenance requires scope resolution outside the miner, not a broad probe. A filesystem path or index declaration does not create authority to inspect private data. Global reusable payloads contain no environment-specific names/paths or forbidden cross-environment references.

Native delegation contract qualification is an independent review prerequisite; this revision must not silently repair model policy.

Index descriptions can be sensitive or misleading. Only opted-in metadata fields are persistable; arbitrary mined prose remains excluded. Cached observations can become stale; queries disclose freshness and actual execution uses live verification. No speed or cost improvement is claimed before measurement.

## UX/design coverage

No graphical UI is proposed. CLI/skill response contract: concise candidates with reasons/source/freshness; bounded context pointers; explicit ambiguity, partial coverage and permission limitations. No raw parser errors containing source content. A graphical browser or dashboard would require a separate UX/design scope.
